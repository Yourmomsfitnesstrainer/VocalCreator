## Область исторического документа

Текущее приложение — принятая рабочая демка 0.1 на основе `bfd2665` (прежняя маркировка 0.3). Ниже сохранены исходные этапы и результаты исследований. Актуальные части слов и плеер описаны контрактами демки, связанными через граф. Старый API `learning` сохраняется для совместимости; исследование упрощения не запускается без нового поручения.

## Purpose & Scope

Контракт локального экрана разучивания вокальной партии v0.2. Пользователь работает в настольном браузере на Mac; принятый дизайн и существующая адаптация сохраняются.

## Surface

@src/karaoke_generator/static/studio.html, @src/karaoke_generator/static/studio.css, @src/karaoke_generator/static/studio.js и @src/karaoke_generator/web.py.
Загрузка файлов, библиотека результатов, waveform, неподвижная клавиатура, ноты, исходный pitch, целые слова, инспектор, overview, Play/Pause, seek, масштаб и независимые gain/mute трёх дорожек.
Переключатель «Подробность мелодии»: Light / Medium / Pro. Учебные JSON и piano WAV готовятся через API из контракта аудио.

## Normative Behavior

1. UI MUST показывать явные статусы стадий, ошибки и доступные результаты без фиктивного процента качества.
2. Play MUST запускать доступные дорожки на одной позиции и одном заранее выбранном времени Web Audio.
3. Pause MUST останавливать все источники и сохранять общую позицию; повторный быстрый клик MUST отменять незавершённый запуск.
4. UI MUST показывать заполненную Play или две заполненные полосы Pause; доступное имя и title MUST соответствовать состоянию.
5. На конце запись MUST возвращаться к Play; следующий запуск MUST начинаться с нуля.
6. Seek MUST останавливать прежние источники и восстанавливать доступные дорожки с общей позиции.
7. Gain/mute MUST менять только выбранную дорожку; при выключенных трёх дорожках время MUST продолжаться.
8. Light MUST быть первым режимом нового открытия; успешно выбранный режим MUST сохраняться локально для ID результата.
9. Подготовка режима MUST сохранять прежний набор нот и пианино до успешной загрузки JSON и декодирования WAV.
10. Смена режима во время звука MUST заменять только piano-source, используя текущие общий clock и offset; вокал и минус MUST продолжать звучать. Если общий старт ещё запланирован на будущее, новый piano-source MUST сохранять это время и не звучать раньше остальных дорожек.
11. Последний запрос режима MUST иметь приоритет над запоздавшими ответами и ошибками; отказ MUST оставлять прежний вариант с объяснением и повторной попыткой.
12. Ноты, интервалы полосок, подсветка, инспектор, счётчики, навигация и piano MUST использовать один активный результат.
13. Смена режима MUST сохранять масштаб и горизонтальную позицию вида; внутренние паузы группы MUST оставаться пустыми на графике и в пианино.
14. Light/Medium MUST обозначаться «Учебное упрощение», Pro — «Подробный разбор»; исходная кривая MUST сохраняться, в упрощённых режимах она приглушена.
15. Слова MUST отображаться один раз на канонических временах; приблизительность и отсутствие ноты MUST иметь текстовое объяснение.
16. Колесо над временной областью MUST сдвигать только вид по времени. Обработчик MUST учитывать deltaMode и доминирующую ось, не суммируя диагональный жест.
17. На краях, над неподвижной клавиатурой и при Ctrl/Cmd-колесе обработчик MUST оставлять событие внешнему управлению.
18. PageUp/PageDown с фокусом на дорожке MUST сдвигать вид на ширину временной области; стрелки на canvas MUST переходить между логическими нотами.
19. Масштаб MUST сохранять время воспроизведения и временной центр видимой области; автоматическое слежение за курсором MUST NOT возвращать ручной вид назад.
20. Глобальный пробел MUST переключать Play/Pause, сохраняя обычное поведение полей, кнопок, ссылок и редактируемого текста.
21. UI MUST исключать A/B, повтор, сброс, отметки интервала и скрытое зацикливание.
22. Скачивание MUST различать исходный melody.json, melody-light/medium/pro.json и piano-light/medium/pro.wav.

## Constraints & Invariants

Один Web Audio clock определяет время дорожек и курсора. Независимые HTML audio не заменяют этот транспорт.
Микшер использует compressor для суммарного выхода; громкость не меняет сохранённые WAV.
Браузерный кеш не должен смешивать новую HTML-разметку со снятыми обработчиками старого JS: index выдаёт URL JS/CSS с хешами содержимого.
Низкое окно допускает вертикальную прокрутку рабочей области; на desktop транспорт и выбор режима закреплены. Временная область сохраняет собственную горизонтальную полосу.
Исходный вокал и минус не упрощаются вместе с учебным пианино.

## Failure Behavior

Нет декодированного аудио — Play недоступна. Ошибка resume/start останавливает уже созданные источники и возвращает Play с причиной.
Нет alignment — Light/Medium недоступны с объяснением; Pro и готовое аудио сохраняются.
Нет совместимого melody — режимы недоступны; исходные готовые дорожки сохраняются.
Частичный результат, ошибка, прерывание или потеря соединения имеют явное объяснение и действие восстановления.
При входе vocal минус недоступен, поскольку сопровождение не загружалось.

## Conformance

@tests/studio_player.test.cjs проверяет общий clock, быстрый кешированный переход до запланированного старта, 10 циклов, конец, отказ и отмену запуска, смену источника, запоздавшие запросы, отказ WAV, интервалы группы, колесо, клавиатуру и масштаб.
@tests/browser_checks.js через @scripts/check_studio_browser.py повторяет ключевые контракты в настоящем браузере и измеряет калибровочные импульсы через OfflineAudioContext.
13 сентября 2026 года: шесть браузерных групп прошли; калибровочная шкала 303,8 с, междорожечный сдвиг 0 мс, показания курсора относительно аудиочаса 0,33 мс. Это программные измерения; физическая задержка аудиоустройства отдельно не измерена.
Сохранённая полная песня открыта в браузере; проверены видимая Pause, режимы, native scroll, PageDown и масштаб. Субъективная музыкальная приёмка и физический трекпад остаются открытыми. Подробности: @docs/vocal-studio-v2-verification.md.
