## Purpose & Scope

Проектируемый локальный экран разучивания вокальной партии, основанный на пользовательском скриншоте Vocal2Melody. Потребитель — владелец Mac в настольном браузере. Нотного стана и послогового режима в первой версии нет.

## Surface

Текущий @src/karaoke_generator/web.py содержит форму и MP4-плеер. Новые статические модули предстоит выделить; их существующих путей пока нет.

Экран: загрузка аудио и TXT; выбор «Песня с музыкой / Готовый вокал»; стадии анализа; waveform; вертикальная клавиатура; полоски нот и кривая pitch; слова; курсор времени; обзор всей записи.
Управление: play/pause, seek, масштаб, выделение A–B и повтор; громкости «Вокал», «Пианино» и «Минус», mute; сохранение WAV; открытие сохранённого результата.
Предлагаемые подписи нот — `До4 (C4)`, `До♯4 (C♯4)` [assumption]; C4 соответствует внутреннему MIDI 60, опорная высота A4 — 440 Hz. Темп/тональность не нужны для базового режима.

## Normative Behavior

1. WHEN пользователь запускает анализ, UI MUST показывать фактическую текущую стадию и состояние задания.
2. WHEN результат готов, UI MUST показывать слова и ноты на единой горизонтальной шкале секунд.
3. WHEN выбранное слово распевается, UI MUST выделять все его связанные ноты.
4. WHEN пользователь запускает воспроизведение, player MUST синхронно запускать вокал, piano и минус по одному аудиочасу.
5. WHEN пользователь перематывает запись, player MUST остановить старые события и восстановить все доступные дорожки на выбранной позиции.
6. WHEN пользователь ставит паузу, player MUST приостановить все доступные дорожки на одной позиции.
7. WHEN пользователь меняет громкость, mixer MUST менять только выбранную дорожку.
8. WHEN пользователь выключает все доступные дорожки, mixer MUST сохранять движение воспроизведения без звука.
9. WHEN пользователь включает повтор A–B, player MUST циклически воспроизводить только выбранный интервал.
10. WHEN пользователь меняет масштаб, UI MUST сохранить текущую позицию и временные границы.
11. WHEN результат частичный, UI MUST показывать доступные дорожки и причины отсутствующих данных.
12. WHEN пользователь возвращается в фоновавшуюся вкладку, UI MUST восстановить курсор по аудиочасу.
13. WHEN слово приблизительно привязано, UI MUST обозначать это текстом или символом кроме цвета.

## Constraints & Invariants

- Независимые HTML audio-дорожки с ручным одновременным play MUST NOT считаться доказанно синхронным transport.
- Player MUST иметь один источник времени для waveform, курсора, слов, нот и трёх дорожек.
- Микшер MUST предотвращать цифровой clipping при сумме дорожек; изменение gain не меняет сохранённые WAV.
- UI MUST сохранять читаемость текущих слов и нот при масштабе без скрытой временной квантизации.
- Пианино MUST дублировать мелодию голоса; минус воспроизводит выделенное сопровождение. Полный оригинал и отдельные инструменты не добавляются в микшер.
- Горячие клавиши и управляющие элементы MUST иметь доступные имена и видимый фокус.
- Студия MUST NOT выставлять фиктивный процент анализа; неизвестный прогресс стадии показывается без процента.

## Failure Behavior

1. IF браузер блокирует автозвук, THEN UI MUST предложить явный запуск пользователем.
2. IF одна дорожка не декодируется, THEN player MUST сообщить её ошибку вместо заявления о полном результате.
3. IF окно A–B пустое или обратное, THEN UI MUST отклонить повтор с указанием причины.
4. IF локальный сервис недоступен, THEN UI MUST сохранить сообщение о потере соединения и действие повторного подключения.
5. IF пользователь загрузил готовый вокал, THEN UI MUST отключить регулятор минуса с пояснением об отсутствии сопровождения.

## Conformance

Проверяются реальный браузер, общий clock, pause/seek, восемь комбинаций mute трёх дорожек, gain, цикл A–B, возврат во вкладку, конец полного файла и открытие сохранённого результата. Критерии Q6 измеряются на калибровочных сигналах и записи длительностью не меньше предоставленного MP3; визуальная проверка скриншота одна их не доказывает.
