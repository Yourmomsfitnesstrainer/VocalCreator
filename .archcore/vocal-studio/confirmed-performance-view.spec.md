## Purpose & Scope
Проект BL-010: проекция подтверждённого исполнения для настольной шкалы, текущей панели и чтения вперёд. Потребитель — @src/karaoke_generator/static/studio.js. Принимается только результат BL-011; исходная лирика и акустические данные остаются отдельными.
Пояснения, область звука и сценарии: @docs/confirmed-lyrics-v1.md, разделы 2, 6, 9. Документ не разрешает реализацию и не меняет текущую демку.
## Surface
Существующие точки: @src/karaoke_generator/learning_v3.py, @src/karaoke_generator/v3_storage.py, @src/karaoke_generator/static/studio.js, @src/karaoke_generator/static/studio.html, @src/karaoke_generator/static/studio.css.
Предлагаемый чистый модуль `src/karaoke_generator/performance_projection.py` принимает подтверждения и неизменяемые акустические события. Его ещё нет.
В `performance.json` используются исходные секунды и следующие поля:
| Поле | Значение |
|---|---|
| `display_notes[]` | `display_id`, `source_note_id`, `start/end`, `midi/cents`, `word_ids[]`, `support_ids[]`; отдельный визуальный фрагмент |
| `text_parts[]` | Только части confirmed-слов: `part_id`, `word_id`, диапазон исходного текста, интервал, `timing_quality`; продолжения задаются связями фрагментов |
| `word_note_links[]` | `word_id`, `display_id`, `source_note_id`, интервал пересечения, источники границ |
| `part_note_links[]` | `part_id`, `display_id`, `start/end`, `continuation`; повторный показ той же части на другом фрагменте |
| `diagnostics` | Число исходных событий, видимых событий/фрагментов, скрытая длительность, confirmed-слова без F0 |
| Маска F0 | Объединение интервалов display_notes; вычисляется один раз при загрузке проекции |
Все ID стабильны при одинаковых входах. Визуальные фрагменты не считаются новыми акустическими атаками.
UI-состояния: `not_prepared`, `preparing`, `ready`, `partial`, `empty`, `unavailable`. `empty` соответствует законченной проверке без допущенных слов; `unavailable` — отсутствию пригодного результата.
Основной текстовый блок называется «Подтверждённая расшифровка»; полная лирика доступна отдельно как «Исходный текст». Подтверждённый экспорт обозначается «Подтверждённая расшифровка TXT/JSON», исходные JSON — «Данные анализа».
## Normative Behavior
1. WHEN готова проверка слов, projector MUST строить проекцию только из confirmed-вхождений.
2. WHEN слово пересекает акустическое событие, projector MUST ограничить видимость подтверждёнными support_intervals.
3. WHEN подтверждён распев, projector MUST сохранить все его связанные нотные интервалы.
4. WHEN возникает реальная пауза, projector MUST оставить разрыв между визуальными интервалами.
5. WHEN одна нота покрывает несколько слов, projector MUST сохранить отдельные подтверждённые области.
6. WHEN скрывается часть ноты, projector MUST сохранить ссылку фрагмента на исходное событие.
7. WHEN projector создаёт фрагмент, синтезатор MUST сохранить прежнее расписание пианино.
8. WHEN нотный интервал не имеет допущенного слова, renderer MUST скрыть его прямоугольник.
9. WHEN интервал скрыт, renderer MUST скрыть соответствующий F0-контур.
10. WHEN между видимыми интервалами есть разрыв, renderer MUST разорвать линию F0.
11. WHEN формируются подписи, renderer MUST исключить nearest, boundary-extension без свидетельства и lyric-context.
12. WHEN слово подтверждено без F0, UI MUST сохранить его в расшифровке и временной строке.
13. WHEN границы части неизвестны, renderer MUST использовать целое подтверждённое слово.
14. WHEN границы приблизительны, UI MUST относить знак ≈ только к соответствующей неопределённости.
15. WHEN исполнитель входит в середину распева, renderer MUST показать читаемую опору его подтверждённого слова.
16. WHEN словесная поддержка под курсором отсутствует, инспектор MUST очистить текущее слово.
17. WHEN текущее слово отсутствует, UI MUST первым показать в «Далее» следующее подтверждённое вступление.
18. WHEN пользователь выбирает элемент, hit-testing MUST учитывать только видимые фрагменты и допущенные слова.
19. WHEN проекция обновляется, UI MUST сбросить выбор, отсутствующий в новой генерации.
20. WHEN UI строит навигацию, UI MUST исключить скрытые элементы из переходов и accessible-названий партии.
21. WHEN UI показывает счётчик партии, UI MUST считать уникальные видимые source_note_id.
22. WHEN пользователь открывает исходный текст, UI MUST сохранить все его символы и вхождения.
23. WHEN исходное слово неподтверждено, UI MUST исключить ложный переход к предполагаемому времени.
24. WHEN расшифровка содержит пропуск, UI MUST исключить восстановление пропущенного исходного текста между допущенными словами.
25. WHEN готовой проекции нет, UI MUST исключить автоматический fallback к старым подписям.
26. WHEN старый разбор открыт, UI MUST предложить явное действие «Проверить слова» при отсутствии проверки.
27. WHEN меняется скорость или масштаб, UI MUST сохранить состояние проверки без запуска моделей.
28. WHEN включено караоке, UI MUST сохранить действующие следование, растры текста и чтение вперёд.
29. WHEN маска скрывает крайние высоты, UI MUST вычислить фиксированный диапазон по видимой партии.
30. WHEN результат пуст, UI MUST сохранить рабочий транспорт и доступ к исходному тексту.
31. WHEN скрываются подписи, UI MUST удалить относящиеся только к контексту пояснения легенды.
32. WHEN показываются причины исключения, UI MUST раскрывать их только в отдельной диагностике.
33. WHEN видимая нота под курсором отсутствует, инспектор MUST очистить только ноту и подсветку клавиши.
34. WHEN подтверждённое слово не имеет ноты, инспектор MUST сохранить текущее слово.
## Constraints & Invariants
- Storage и projector MUST сохранять акустические notes, pitch_frames, WAV, piano events и исходные времена.
- UI MUST NOT рисовать «Нет текста», выдуманные буквы, контекстные слова и пустые заменители скрытых событий.
- Геометрия MUST зависеть от времён и масштаба, а не от факта пропуска; сжатие временной оси запрещено.
- Подтверждение слова MUST оставаться отдельным от статуса слоговой границы; BL-002 не реализуется.
- Распев MUST сохранять единый word ID; новый display-фрагмент не создаёт повтор текста в TXT.
- Current-word MUST определяться support_intervals, current-note — display_notes; наличие слова не требует F0.
- Support за границей слова MUST иметь локальное акустическое свидетельство того же вхождения; расстояние 0.35 с и сходство F0 недостаточны.
- Диапазон высот MUST оставаться постоянным при воспроизведении; пустая партия использует нейтральный диапазон C3–C5 без нот.
- Waveform MUST сохранять полный обзор аудио; это не распознанная партия.
- Панели текущего и будущего текста MUST сохранять высоту при паузе, пропусках и смене статуса.
- Караоке MUST оставлять минимум 3 секунды реального времени справа; ручная прокрутка переводит following в suspended.
- Транспорт MUST сохранять общий Web Audio clock, исходную позицию и скорость; проекция не пересоздаёт аудиобуферы.
- Экран MUST сохранять интерфейс демки 0.1 без новых режимов подробности и мобильной компоновки.
- Обработчик ответа MUST проверять job ID, generation ID и request token перед заменой проекции.
- UI MUST экранировать пользовательский текст; HTML из TXT не исполняется.
## Failure Behavior
1. IF результат пуст после проверки, THEN UI MUST показать вне партии «Не удалось подтвердить слова по аудио и тексту».
2. IF проверки старого разбора нет, THEN UI MUST показать «Для этого разбора слова ещё не проверены».
3. IF подготовка идёт, THEN UI MUST показывать статус вне партии без выдуманных промежуточных подписей.
4. IF новая генерация повреждена, THEN UI MUST сохранить предыдущую совместимую целую проекцию с объяснением ошибки.
5. IF предыдущая проекция относится к другим входам, THEN UI MUST показать unavailable вместо неё.
6. IF отдельная стадия проверки отказала, THEN UI MUST обозначить partial и показать только опубликованный подтверждённый поднабор.
7. IF current-word отсутствует, THEN follow-контроллер MUST продолжить следование по аудиочасу.
8. IF скрытый элемент остался в старом выборе, THEN UI MUST очистить выбор до следующего кадра.
## Conformance
Сценарии A06–A20 из @docs/confirmed-lyrics-v1.md проверяются в @tests/studio_player.test.cjs, @tests/browser_checks.js и новых `tests/test_performance_projection.py`.
SHA пианино проверяется до/после построения проекции; звуковые атаки сравниваются отдельно от количества визуальных фрагментов. F0 проверяется на наличие разрывов, а не только на отсутствие подписей в DOM.
Проверка реального продукта охватывает обе песни через @scripts/check_reference_song.py и новые вкладки desktop-браузера, включая окно 1280×600.
