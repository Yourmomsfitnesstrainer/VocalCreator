## Purpose & Scope

Утверждённый контракт чтения вокальной шкалы и режима караоке для пользователя desktop-студии. Источник требований и примеры — @docs/tz-reading-and-karaoke-follow-v1.md. Пользователь утвердил ТЗ и запуск разработки 14 сентября 2026 года; реализация выполняется в отдельной задаче GPT-6 Astra xhigh. Анализ аудио, слогоделение и заливка BL-003 исключены.

## Surface

@src/karaoke_generator/static/studio.js: `drawTimeline`, `noteLabels`, `timelineLabelSpans`, `renderInspector`, `tick`, `seek`, обработчики масштаба и прокрутки.
@src/karaoke_generator/static/studio.html и @src/karaoke_generator/static/studio.css: панель исполнения, внешний слой подписей, переключатель и возврат.
Входные данные: исходные ноты, звучащие интервалы, существующие связи слов и частей, общий audio clock.
Состояния режима: `off`, `following`, `suspended`. Отдельный признак play/pause сохраняется.

## Normative Behavior

1. При наличии нескольких word_id в ноте renderer MUST различать их временные области по существующим связям.
2. При неподписанном промежутке внутри звучащей ноты renderer MUST сохранять его как область без текстовой привязки.
3. При отрисовке слов renderer MUST сохранять исходный временной контур нотного события.
4. При выборе участка слова инспектор MUST раскрывать его word_id и исходную ноту.
5. При навигации между нотами UI MUST считать исходные акустические события.
6. При продолжении одной части renderer MUST сохранять полную опору и обозначения продолжения.
7. При выводе подписи renderer MUST размещать текст во внешнем слое над нотами.
8. При изменении масштаба renderer MUST сохранять внешнее размещение независимо от размера прямоугольника.
9. При нехватке места renderer MUST исключать наложения по приоритету текущей и выбранной групп.
10. При скрытой опоре группы renderer MUST исключать её отдельные неподписанные знаки продолжения.
11. При прокрутке renderer MUST восстанавливать опору доступной группы по обеим осям.
12. При смене содержимого панель исполнения MUST сохранять свою высоту в текущей desktop-компоновке.
13. При смене ноты внутри слова панель MUST сохранять текстовые элементы этого word_id и соседей.
14. При запросе подробностей UI MUST показывать полную диагностику без сдвига шкалы.
15. При первом открытии настройка режима караоке MUST иметь значение `off`.
16. При переключении режима UI MUST сохранять выбор локально.
17. При включении режима контроллер MUST однократно показывать текущую позицию без изменения play/pause.
18. При воспроизведении в `following` контроллер MUST вычислять горизонтальную позицию по общему аудиовремени.
19. При нахождении текущей ноты в вертикальной безопасной области контроллер MUST сохранять вертикальный вид.
20. При выходе ноты из безопасной области контроллер MUST переводить её в видимую центральную область.
21. При реальном ручном перемещении шкалы контроллер MUST переходить из `following` в `suspended`.
22. При программном перемещении контроллер MUST сохранять состояние следования.
23. При нажатии возврата контроллер MUST переходить в `following` без изменения play/pause.
24. При обычной паузе контроллер MUST прекращать движение окна.
25. При смене скорости или режима мелодии контроллер MUST сохранять состояние следования.
26. При возвращении фоновой вкладки контроллер MUST использовать текущую аудиопозицию без очереди старых перемещений.
27. При завершении трека контроллер MUST прекращать автоматическое движение.

## Constraints & Invariants

Проверяемые параметры: опора времени 35% полезной ширины, допуск 2 CSS px; вертикальная безопасная область 20–80%, обзор 2 секунды; стабильность панели 1 CSS px.

Renderer MUST сохранять canonical_text, words, text_parts, note_text_links, labels, ID и исходные времена.
Контроллер MUST сохранять аудиобуферы, расписание атак, паузы, синхронность дорожек и выбранный масштаб.
Renderer MUST сохранять полный текст и пунктуацию в лирике и доступном представлении.
UI MUST сохранять явный контекст, приблизительность, причины fallback и сообщения.
Контроллер MUST перемещать только внутреннюю область нотной шкалы.
Контроллер MUST сохранять фокус пользователя.
UI MUST различать выключенный режим и временный ручной просмотр.
При перезагрузке UI MUST сбрасывать временное состояние `suspended`.

Пользователь утвердил ручную приостановку следования до нажатия кнопки возврата вместе с ТЗ 14 сентября 2026 года. Опорный диапазон и обзор являются параметрами проекта, а не новыми оценками акустики.

## Failure Behavior

1. Если временных связей недостаточно, renderer MUST сохранять полную исходную ноту с явным объяснением отсутствующей границы.
2. Если связи слов перекрываются, renderer MUST сохранять оба слова с признаком спорной границы.
3. Если текущих нот нет, контроллер MUST сохранять последнюю высоту с горизонтальным следованием времени.
4. Если близкая следующая нота известна, контроллер MAY предварительно показать её в пределах обзора.
5. Если диапазон будущих нот не помещается, контроллер MUST отдавать приоритет текущей ноте.
6. Если локальная настройка недоступна, UI MUST сохранять работоспособность переключателя в текущей вкладке.
7. Если достигнут край прокрутки, контроллер MUST ограничивать положение реальным диапазоном.
8. Если включено уменьшение движения, контроллер MUST исключать декоративное сглаживание вертикальных переходов.

## Conformance

Приёмка — A01–A15 из @docs/tz-reading-and-karaoke-follow-v1.md.
Проверки Canvas/DOM, геометрии и автомата состояний реализованы в @tests/studio_player.test.cjs и @tests/browser_checks.js.
Постоянная песня проверяется через @scripts/check_reference_song.py и настоящий desktop-браузер. Файлы и расписание пианино сравниваются до/после. Реализация проверена 14 сентября 2026 года на сохранённом Seekae без повторного запуска моделей.

## Реализация и проверка 14 сентября 2026 года

`noteWordRegions` пересекает временные связи с исходными звучащими интервалами. `timelineHits` сохраняет исходную ноту и все связанные word_id/part_id; неподписанная область звучит непрерывно. При неполных временах нота остаётся целой, при перекрытии обе связи доступны в подробностях.

`layoutTimelineLabels` размещает полный текст и продолжения только снаружи прямоугольников, проверяет пересечения с нотами и подписями, сохраняет опору по обеим осям. Над нотной областью зарезервирован внешний ряд для обрезанных верхним краем нот. При дефиците места текущая и выбранная группы имеют приоритет; скрытая опора не оставляет отдельных черт. Размещение кешируется по данным и геометрии вида.

Панель исполнения имеет высоту 104 CSS px, при ширине desktop-окна до 1100 px — 140 CSS px. Слово и соседи не пересоздаются при переходе между нотами одного word_id. Приблизительность связи видна в короткой строке; полный текст, причины и ID открываются в нативном dialog с собственной прокруткой, Escape и восстановлением фокуса.

`followPosition` вызывается существующим `tick` и использует `currentPosition()`. Опора времени — 35%; вертикальная область 20–80% считается от нотной части canvas ниже внешнего ряда. Обзор — две секунды; высота не масштабируется. У вертикального перехода одна заменяемая цель и экспоненциальное сглаживание 85 мс; текущая нота остаётся видимой, reduced-motion переводит вид сразу. `moveTimeline` запоминает фактически ограниченные браузером координаты. Прокрутка, не совпавшая с ними, приостанавливает следование; таймера возврата нет. После клавиатурного возврата кнопка сохраняет фокус и остаётся доступной до его перевода на другой элемент. Локальный ключ — `vocalcreator:karaoke-follow`, временное состояние не сохраняется.

Выполнены 54 JS-теста, 104 подходящие Python-регрессии, проверки настоящего браузера и API постоянной песни. Размеры: 1280×600, 1280×720, 1440×900, 1024×768. Дрейф панели — 0 px; ошибка позиции нарисованного курсора от опоры — менее 0.3 px. Проверены Light/Medium/Pro при 1× и 0.5×, дополнительно 0.25× и 2×. Все 83 исходно сохранённых файла совпали по SHA-256; во всех режимах сохранены 305 слов и 771 атака пианино. Акустическая точность и слогоделение этим изменением не переоцениваются. BL-002 и BL-003 остаются открытыми.

## Дальнейшие пожелания пользователя — 14 сентября 2026 года

После проверки пользователь положительно оценил текущую студию и следование. В @docs/backlog.md записаны BL-004–BL-009: отказ от Karaoke MP4 с сохранением нужных студии частей; удаление выбора Light/Medium/Pro; общая легенда значков вместо повторения расшифровок у текущей части; расширенный экран исполнения; неподвижные фрагменты партии с движущимся курсором; заблаговременный показ следующих слов. Бэклог содержит границы задач и критерии результата. Предполагаемая связь «плавающих» букв с масштабом ещё не проверена; алгоритм смены фрагментов и запас времени на чтение предстоит определить.

Это поручение на запись будущих задач. Оно не запускает реализацию или модели и не заменяет описанное выше текущее поведение. При отдельной проработке BL-007–BL-009 потребуется пересмотреть контракт непрерывного следования с опорой 35%, сохранив синхронность звука, ручную приостановку, возврат и исходные данные. BL-001–BL-003 остаются в бэклоге.
