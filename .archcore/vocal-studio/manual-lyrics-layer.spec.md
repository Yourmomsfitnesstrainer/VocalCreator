## Purpose & Scope
Уточнение направления от 14 сентября 2026 года: новый основной интерфейс определяется @docs/syllable-score-v1.md. Отдельная словесная полка и строки ролей в новом сценарии заменяются коррекцией слогов над нотами. Ниже сохранён контракт существующего редактора для архивной совместимости и повторного использования хранения; это не поручение продолжать прежний интерфейс.

Контракт слоя разметки, которым пользуются десктопный редактор, автоматические предложения и оценщик. Требования пользователя: @docs/manual-lyrics-editor-v1.md. Общая мелодия и звуковые дорожки остаются исходными.

## Surface
@src/karaoke_generator/manual_lyrics.py и @src/karaoke_generator/manual_web.py: локальные проекты и неизменяемые снимки. @src/karaoke_generator/static/manual-model.js и @src/karaoke_generator/static/manual-editor.js: команды редактирования, история, роли и проверка.
API `/api/studio/jobs/{id}/manual`: GET проекта, PUT ревизии, `/references` для снимков, `/import` для совместимого восстановления.
`manual-lyrics.json` хранит черновик; `manual-references/{id}.json` хранит версии проверенных фрагментов.

## Normative Behavior
1. При первом открытии storage MUST импортировать собственные времена слов и частей по ID.
2. При сохранении storage MUST сравнить ревизию перед атомарной записью.
3. При копировании редактор MUST создать независимые ID плашек и исполнений.
4. При вставке редактор MUST сохранить существующие целевые плашки.
5. При движении группы редактор MUST ограничить общий сдвиг границами записи.
6. При назначении роли редактор MUST использовать список выбора.
7. При удалении роли редактор MUST перенести её плашки в пул «Без роли».
8. При фильтрации плеер MUST скрыть слова выбранных ролей во всех областях исполнения.
9. При входе в редактор UI MUST показать все роли.
10. При завершении редактор MUST сохранить слой перед возвратом к общему полотну.
11. При смысловой правке storage MUST снять проверку затронутого интервала.
12. При создании эталона storage MUST зафиксировать снимок сохранённой ревизии.
13. При проверке интервала storage MUST учитывать все роли.
14. При неопределённости storage MUST исключить соответствующее измерение из проверенных признаков.
15. При пограничном слове storage MUST подтвердить только признаки внутри проверенного интервала.
16. При изменении цвета роли storage MUST сохранить смысловую проверку.

## Constraints & Invariants
Плашка и исполнение имеют разные ID; части одного слова объединяются исполнением. Длительность выводится из границ. Вертикальное перетаскивание отсутствует. Перекрытия допустимы; копия части остаётся неполным исполнением.
Исходные TXT, alignment, pitch, ноты и звук не переписываются. Сохранение и фильтрация не запускают вычисление моделей или темпа. Сохранение проекта не означает проверки человеком.
Проверка хранит маски наличия, текста, начала, конца и роли. Подтверждённый пустой интервал допустим. Имена и цвета ролей не являются идентичностью певца.
Пользовательские данные остаются локально вне Git. Десктопная платформа включает низкие окна.

## Failure Behavior
1. При конфликте ревизии API MUST вернуть 409 с объяснением.
2. При ошибке записи редактор MUST сохранить несохранённое состояние доступным для экспорта.
3. При несовпадении хешей storage MUST отказать в переносе на чужие исходники.
4. При исчезновении исходника API MUST указать файл для восстановления.
5. При вставке за конец записи редактор MUST отклонить всю группу.
6. При невалидном вводе времени редактор MUST сохранить прежние границы до исправления поля.

## Conformance
@tests/test_manual_lyrics.py проверяет ревизии, источники, атомарность, маски и снимки. Проверки редактора находятся в @tests/manual_model.test.cjs. @scripts/check_reference_song.py выполняет обе постоянные песни. Доказательства продуктовой проверки собираются в @docs/manual-lyrics-editor-verification.md.
