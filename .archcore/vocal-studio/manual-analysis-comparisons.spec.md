## Purpose & Scope
Уточнение направления от 14 сентября 2026 года: @docs/syllable-score-v1.md ограничивает ближайший этап слогами ведущего голоса. Автоматические роли и расширение циклов сравнения в новом этапе не выполняются; существующие файлы, профили, эталоны и история сохраняются. Ниже описан прежний функциональный контур.

Контракт локальных автоматических предложений и повторяемых циклов сравнения, которым пользуются редактор и владелец эталонов. Настройка весов моделей отсутствует; длительная оценка качества зависит от будущего пользовательского корпуса.

## Surface
@src/karaoke_generator/manual_auto.py: предложения размещения, повторов и тембровых ролей. @src/karaoke_generator/manual_evaluation.py: оценка исполнений с масками проверки.
@src/karaoke_generator/manual_cycles.py и @src/karaoke_generator/manual_cycles_web.py: корпус, снимки исполняемых профилей, запуск и история.
`POST /api/studio/jobs/{id}/manual/auto` создаёт отдельный производный результат. `/api/studio/manual-lab` предоставляет корпус, профили и циклы. @src/karaoke_generator/static/manual-cycles.html открывает сравнение.
Локальный каталог `manual-lab` расположен рядом с `jobs`; автоматические версии находятся в `result/manual-auto`.

## Normative Behavior
1. При автоматическом предложении текста анализатор MUST брать написание из TXT текущей песни.
2. При обнаружении повтора анализатор MUST создать отдельное исполнение с происхождением.
3. При предложении ролей анализатор MUST обработать фактический вокальный PCM.
4. При неопределённой роли анализатор MUST сохранить исполнение в пуле «Без роли».
5. При повторном анализе API MUST создать отдельный результат.
6. При фиксации профиля storage MUST сохранить исполняемый код и параметры.
7. При запуске профиля worker MUST исполнить сохранённую версию кода.
8. При запуске цикла storage MUST зафиксировать точные версии корпуса и профилей.
9. При повторном цикле storage MUST сохранить предыдущую историю.
10. При сравнении оценщик MUST сопоставить исполнения взаимно однозначно.
11. При сравнении ролей оценщик MUST применить одно соответствие на всю песню.
12. При неполной группе оценщик MUST отделить части от метрик целых слов.
13. При отсутствии проверенной разметки оценщик MUST вернуть недоступность метрик.
14. При принятии профиля storage MUST изменить только выбранный язык.
15. При возврате профиля worker MUST использовать код предыдущей версии.
16. При сохранении эталона приложение MUST оставить запуск расчётов явному действию пользователя.

## Constraints & Invariants
Начальная настройка: три разных проверенных EN и три RU. Контроль: одна EN и одна RU вне настройки. Постоянная контрольная пара разрешена между циклами; после разработки по её ошибкам она не является независимой проверкой новых песен.
Неизменённые акустические стадии используют проверенные входы; новая стадия предложений исполняется отдельно. Автоматическая версия не получает ручные ответы контрольных эталонов на вход.
Роли — приблизительные группы спектральных признаков; они могут зависеть от фонем и эффектов. Общий pitch не используется как доказательство идентичности певца. Точность наложенного тихого голоса не гарантируется.
До предоставления корпуса и решений пользователя улучшение качества не объявляется доказанным. Самостоятельное сохранение профиля не принимает его.

## Failure Behavior
1. При повреждении снимка кода worker MUST отказать в запуске.
2. При изменении зависимостей профиля worker MUST указать необходимость восстановления окружения.
3. При недостаточном корпусе API MUST отклонить запуск с перечнем недостающего состава.
4. При ошибке расчёта storage MUST сохранить ошибку и уже полученные результаты.
5. При отсутствии пользовательской оценки API MUST отказать в принятии кандидата.
6. При несовместимых исходниках оценщик MUST отказаться от сравнения.

## Conformance
@tests/test_manual_auto.py, @tests/test_manual_evaluation.py и @tests/test_manual_cycles.py проверяют реальные признаки аудио, дополнительные исполнения, ошибки метрик, воспроизводимость и историю. @scripts/create_manual_lab_fixture.py создаёт отдельный синтетический набор для проверки интерфейса; он не является человеческим корпусом. Продуктовая проверка двух постоянных песен описывается в @docs/manual-lyrics-editor-verification.md.
