## Purpose & Scope

Проектируемый контракт аудиовхода и сохранённого результата вокальной студии. Потребители — анализ мелодии, привязка текста, плеер. Текущая karaoke-генерация продолжает использовать свой контракт до отдельной адресной доработки.

## Surface

Точки интеграции: @src/karaoke_generator/audio.py, @src/karaoke_generator/separation.py, @src/karaoke_generator/pipeline.py, @src/karaoke_generator/timing_cache.py, @src/karaoke_generator/web.py.

Предлагаемые поля задания: тип входа `mix|vocal`, аудио, UTF-8 TXT, язык `auto|ru|en`. Тип `vocal` выбирает пользователь; приложение не объявляет такой файл проверенным чистым голосом.

Предлагаемые артефакты: `vocals.wav`, `instrumental.wav` для полного микса, существующий `alignment.json`, отдельный `melody.json`, `piano.wav`, `studio.json`, исходный TXT и отчёт его очистки. `studio.json` связывает версии, пути, длительность, статусы стадий и происхождение. Схема студии начинается с версии 1; это проектируемые имена, кода ещё нет.
При полном провале ASR поле `alignment.status` равно `unavailable`; TXT доступен без времён, фиктивный alignment JSON отсутствует. Имеющаяся валидная ручная разметка сохраняется.

## Normative Behavior

1. WHEN пользователь запускает анализ микса, pipeline MUST получить вокальную и инструментальную дорожки успешным separator.
2. WHEN пользователь выбирает готовый вокал, pipeline MUST записать происхождение дорожки как `provided_vocal`.
3. WHEN декодирование завершено, audio MUST использовать первый декодированный сэмпл как ноль общей шкалы.
4. WHEN стадия завершена, pipeline MUST атомарно сохранить её результат и статус.
5. WHEN separation завершён, pipeline MUST записать backend, параметры, ревизию и SHA-256 весов.
6. WHEN анализ студии завершён, pipeline MUST завершить задание без обязательного ASS или MP4.
7. WHEN пользователь сохраняет вокал, API MUST отдавать только существующий аудиоартефакт из проверенного списка.
8. WHEN приложение перезапускается, storage MUST восстановить список завершённых результатов из сохранённых манифестов.
9. WHEN процесс анализа прерывается, storage MUST пометить незавершённое задание как прерванное.
10. WHEN повторный запуск использует кеш, pipeline MUST проверить хеши входа, параметры, версии алгоритма, runtime и моделей.
11. WHEN меняются слова, pipeline MUST повторно использовать совместимые separation и pitch результаты.
12. WHEN меняется громкость или масштаб, pipeline MUST сохранить результаты всех ML-стадий.

## Constraints & Invariants

- Все времена MUST относиться к декодированному оригиналу; crop хранит `source_offset_sec`. Resampling и оконный анализ учитывают origin один раз.
- Успешный separator MUST сохранять длительность и временную позицию голоса и минуса. Корреляционная диагностика общей шкалы не измеряет чистоту вокала.
- Минус из полной песни MUST сохранять исходное сопровождение, включая все его инструменты; отдельные instrument stems не требуются.
- При входе `vocal` минус MUST иметь статус `unavailable`, поскольку исходное сопровождение отсутствует.
- Студия MUST различать `separated`, `provided_vocal`, `failed`; существующий `original-audio` не является успешным выделением.
- Исходники и ручные канонические границы слов MUST сохраняться. Промежуточный формат для ML не подменяет аудио для прослушивания.
- Результаты MUST храниться в постоянном локальном каталоге, исключённом из Git; системный временный каталог не является библиотекой.
- Приложение MUST сохранять результаты до явного удаления пользователем. Автоматическое удаление и облачная синхронизация не входят.
- HTTP MUST по умолчанию слушать loopback; разрешённые артефакты ограничиваются каталогом соответствующего задания.
- Студия MUST использовать независимые кеши separation, pitch, notes, word-note mapping и piano. Изменение TXT может инвалидировать ASR при включённом lyrics prompt.

## Failure Behavior

1. IF separator отсутствует или завершается ошибкой, THEN pipeline MUST сообщить ошибку выделения вместо публикации микса как вокала.
2. IF ввод пустой, повреждённый или неподдерживаемый, THEN API MUST сообщить причину до запуска тяжёлого анализа.
3. IF проверка временной шкалы обнаруживает сдвиг, THEN pipeline MUST остановить зависимые стадии.
4. IF проверка шкалы неубедительна, THEN metadata MUST сохранить `inconclusive` без заявления о подтверждённой синхронности.
5. IF анализ текста или мелодии не завершился, THEN storage MUST сохранить уже полученные вокал и минус.
6. IF сохранённый формат неизвестен, THEN reader MUST сообщить несовместимость без перезаписи файлов.

## Conformance

Проверяются ложный успех separator, происхождение готового вокала, запрет path traversal, перезапуск, частичный результат, точная шкала и независимость кешей. Акустические метрики проверяются отдельно; файл с именем `vocals.wav` сам по себе не доказывает выполнение контракта.
