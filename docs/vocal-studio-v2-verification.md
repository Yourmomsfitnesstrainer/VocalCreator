# Проверка реализации VocalCreator 0.2

Дата: 13 сентября 2026 года. Ветка: `version-0.2`, основа `6229eb1`.
Основание: прямое поручение исполнить и проверить [ТЗ v2](vocal-studio-tz-v2.md).
Статус: реализация и программная проверка выполнены; независимая музыкальная приёмка открыта. Коммит, публикация и слияние не выполнялись.

## Реализованное поведение

- Заполненные Play/Pause, синхронные доступное имя и подсказка, отмена незавершённого запуска, остановка созданных источников при ошибке. Весь A–B удалён.
- Учебная группа с одной высотой и массивом звучащих интервалов: Light — одна группа на слово, Medium — до двух последовательных групп. Разрыв внутри группы сохраняется в полоске и WAV. Pro хранит отдельные поддержанные события без лимита на слово.
- Отдельная сегментация Pro из сохранённого pitch: гистерезис, проверка устойчивого перехода, явные разрывы voiced и признаки повторной атаки по RMS сохранённого вокала. Исходные кадры, события и многие-ко-многим пересечения остаются в прежнем файле.
- Light/Medium используют наблюдавшиеся высоты, учитывая длительность и confidence. Вторая группа Medium выбирается по одной исходной границе с улучшением ошибки представления и штрафом за границу; деления слова пополам нет.
- При недостатке данных слово сохраняется без ноты. Аномальные приблизительные интервалы помечаются «Проверьте привязку слова»; ручная длинная граница не отбрасывается только за длительность.
- Режим меняет согласованно ноты, инспектор, счётчики, навигацию и пианино. Во время проигрывания заменяется только piano-source на текущей позиции общего clock. Запоздалый ответ и ошибка не подменяют последний запрос или рабочий вариант.
- Light по умолчанию, локальное сохранение последнего успешно выбранного режима на результат. Скачивание явно различает исходные ноты, `melody-{mode}.json` и `piano-{mode}.wav`.
- Колесо, горизонтальный и диагональный жесты используют доминирующую ось и deltaMode; края и системный zoom не перехватываются. PageUp/PageDown сдвигают вид. Масштаб сохраняет центр времени; ручная прокрутка не включает автослежение.
- Хешированные URL JS/CSS предотвращают смешение новой страницы со старыми обработчиками из браузерного кеша. На низком desktop-окне доступна вертикальная прокрутка рабочей области.

## Сохранённые данные и API

`POST /api/studio/jobs/{job_id}/learning/{mode}` подготавливает JSON и WAV; `GET /api/studio/jobs/{job_id}/learning/{mode}/{cache_key}/{filename}` отдаёт только два разрешённых файла с подписью режима.
Результаты находятся в `result/learning`, исходные артефакты не переписываются. Подготовка использует временный каталог и атомарный rename; внутри процесса запросы сериализованы. Не зарегистрированный в текущем manifest старый alignment не используется.

Ключ учитывает семантические SHA-256 исходных JSON, байтовый SHA-256 вокала, версии alignment/segmentation/learning/piano, параметры и режим. Для старого результата без pitch-кадров допускается сохранённый список событий с явным ограничением диагностики. Повторная тяжёлая обработка при переключении режима не запускается.

Браузерная калибровка: Chromium 152, шкала 303,8 с; импульсы в начале, середине и конце. Записанные production-времена запуска отрисованы через `OfflineAudioContext`: междорожечный сдвиг **0 мс**. Расхождение показания курсора и общего аудиочаса в контрольной точке — **0,33 мс**. Допуски 20/50 мс выполнены для этой программной проверки; физическая задержка устройства и полный аудиотракт до слуха не измерены.

Fault probes в изолированных копиях: sentinel в выборе высоты; снятие лимита Light; заполнение внутренней паузы; исключение канонических слов из ключа кеша; принятие запоздалого режима. Сохранены точные diff, коды завершения и результаты восстановления в локальном `output/v2-qa/fault-probes.json`. Изменённые варианты в рабочем коде не оставлены.

Итоговая сверка выявила преждевременный старт пианино при переключении кешированного режима в первые 20 мс после Play. Исправление сохраняет запланированное общее время запуска. Новый регрессионный тест сначала упал на прежнем коде, затем прошёл на границах 0/5/19/20/25 мс. Дополнительные три изолированные пробы (sentinel, ранний старт, потеря offset) обнаружены; восстановленные варианты прошли. Доказательства: `output/v2-qa/start-clock-probes.json`. Повторная проверка реального Web Audio подтвердила сдвиг общей временной шкалы при такой смене **0 мс**; все шесть браузерных групп прошли.

Механический Impeccable detector сообщил предупреждения об унаследованных размерах текста 10–11 px и advisory по исходным токенам палитры/радиусов. Общий дизайн в рамках ТЗ не перерабатывался. Desktop проверен на 1280×720; отдельная успешная проверка мобильного viewport в этом запуске не заявляется.

## Наблюдения на пользовательской песне

Сохранённый результат `ce061ea2ca7741abbd6693824f1f9c39`, длительность 303,725714 с. Исходно 699 нот и 305 слов.

| Режим | Логические единицы | Слова | Слова без учебной ноты или с проверкой времени |
|---|---:|---:|---:|
| Light | 247 | 305 | 58 |
| Medium | 296 | 305 | 58 |
| Pro | 778 | 305 | 57 |

Суммарное число Medium больше Light, при этом на одно слово приходится не больше двух групп. Число Pro отличается от старых 699 событий из-за отдельной сегментации и повторных атак. Эти числа не доказывают улучшение музыкальной точности.

Сравнение байтовых SHA-256 всех исходных файлов до и после подготовки трёх режимов подтвердило их сохранность. Первичная подготовка через прямой локальный вызов заняла 0,879 / 0,316 / 0,400 с соответственно; это единичные измерения, не обещание времени в других условиях и не время декодирования аудио браузером.

## Параметры и незавершённая приёмка

Синтетические ожидания записаны до реализации в `tests/fixtures/learning/contracts.json`: четыре ноты, вибрато, внутренняя пауза, быстрый мелизм, повторная атака, короткое слово, длинное слово, портаменто, неточная привязка. Три случая выделены как calibration, шесть — holdout. Это авторские синтетические контракты; они не заменяют восемь вручную размеченных фрагментов настоящего пения.

Рабочие параметры пока инженерные: минимальная поддержка 60 мс, переход 0,8 полутона, диапазон плато 0,45 полутона; confidence floor 0,45; фильтр приблизительной длительности 40 мс–2,5 с. Параметры RMS-атак, значимости пересечения и Medium хранятся в JSON результата. На пользовательской песне эти пороги не подгонялись. До итоговой музыкальной приёмки они требуют отдельной калибровки по независимым данным.

`scripts/prepare_learning_acceptance.py` создал восемь шестисекундных кандидатов из текущей песни: начала 27,700; 79,250; 99,550; 144,790; 170,490; 196,110; 218,570; 247,400 с. У каждого есть исходный вокал и Light/Medium/Pro piano. Пакет находится в исключённом из Git `output/v2-qa/listening/`; `index.html` открывает прослушивание, `annotations.json` содержит пустую ручную разметку. Первые четыре фрагмента назначены для калибровки, последние четыре для отдельной проверки.

Автоматический выбор кандидатов не устанавливает музыкальный тип каждого фрагмента. Нужно независимо подтвердить покрытие восьми случаев из ТЗ, выбрать другие участки при необходимости, разметить ноты/атаки/паузы и затем оценить, легче ли следовать нотам, узнаётся ли мелодия и нет ли ложных скачков. Пользовательское прослушивание и пение, физическая чувствительность мыши/трекпада и прежняя акустическая приёмка Q1–Q7 остаются открытыми.
