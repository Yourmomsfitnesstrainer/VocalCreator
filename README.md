# VocalCreator

Локальная десктопная вокальная студия, демка **0.1**. Аудио и точный текст превращаются в вокал, минус, полную мелодию, пианино и связи слов с нотами. Исходники и результаты остаются на этом компьютере.

Ветка `codex/karaoke-reading` реализует BL-004–BL-009 с уточнением пользователя от 14 сентября 2026 года: **непрерывное следование сохраняется**, статичные экраны и переключение фрагментов отменены. [Требования и проверка](docs/karaoke-reading-v1.md).

## Запуск на macOS

Нужны Python 3.10–3.13, FFmpeg и Rubber Band 3+ для изменения темпа. На проверенном Mac используется Python 3.12.

```bash
brew install ffmpeg rubberband
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[ml,web,dev,separation,studio]'
PYTHONPATH=src .venv/bin/python -m karaoke_generator web --port 8080
```

Откройте [локальную студию](http://127.0.0.1:8080). Выберите аудио и UTF-8 TXT либо сохранённый разбор. По умолчанию используется WhisperX, Demucs htdemucs и torchcrepe full; первый запуск скачивает веса. `uniform` и `autocorrelation` — явно выбираемые диагностические backend, не автоматическая замена ML.

Дополнительный separator устанавливается через `pip install -e '.[studio-roformer]'`. Mel-Band RoFormer на проверенной связке использует CPU из-за неподдерживаемой операции complex scatter на MPS; фактический device и происхождение модели сохраняются в результате.

CLI:

```bash
karaoke-gen studio --audio song.mp3 --lyrics lyrics.txt --output studio-result --input-type mix --language en
karaoke-gen doctor
karaoke-gen web --host 127.0.0.1 --port 8080
```

Для уже выделенного голоса задайте `--input-type vocal`: минус помечается отсутствующим. В `mix` ошибка separator завершает анализ ошибкой; исходный микс не выдаётся за вокал.

Создание караоке-видео удалено: нет экрана MP4, команд `generate`/`render`, ASS-рендерера, видеофонов и требования libass. Ранее сохранённые файлы не удаляются.

## Чтение и воспроизведение

- Доступна одна полная мелодия: все устойчивые переходы, паузы и связи с текстом сохраняются. Части слова не создают дополнительные атаки пианино.
- Три дорожки используют общий аудиочас; громкость и mute независимы. Скорость 0,25–2× подготавливается совместным Rubber Band R3-процессом без изменения высоты. До готовности действует прежняя скорость.
- «Режим караоке» расширяет партию на всё рабочее окно. Непрерывное горизонтальное следование сохраняет курсор около 35% ширины. Диапазон всех нот помещается по высоте и не перемещается при переходах.
- Подписи сохраняют размещение при смене слов. Растр букв кешируется и перемещается по пиксельной сетке, чтобы дробная прокрутка не меняла очертания букв.
- Справа оставляется минимум три секунды реального времени для чтения следующих слов. При сильном увеличении масштаб ограничивается; выбранное значение сохраняется для обычного режима. Строка «Далее» показывает предстоящие слова, включая переходы без паузы.
- Колесо, горизонтальный жест и Shift + PageUp/PageDown приостанавливают следование. Кнопка «К исполнению» возвращает его, сохраняя play/pause. Выход возвращает вид обычной студии.
- Общая легенда сверху объясняет значки. Возле текущего слова остаются символы; полные причины, ID и диагностические данные доступны в «Подробностях».

Слогоделение остаётся автоматической оценкой. `≈` обозначает приблизительность, `к` — неподтверждённый контекст, `…` — отсутствие точной части, `?` — перекрытие связей, `∅` — отсутствие связи, `─` — продолжение. Полный канонический текст сохраняет пунктуацию и все повторы.

## Данные и совместимость

Библиотека: `~/Library/Application Support/VocalCreator/jobs`. Переменная `VOCAL_CREATOR_DATA_DIR` задаёт базу, внутри которой создаётся `jobs/`. Сохраняются `studio.json`, WAV, `melody.json`, `alignment.json`, TXT и отчёт очистки. Частичный анализ оставляет доступные результаты; перезапуск помечает незавершённое задание как прерванное.

Тяжёлые стадии и производные данные имеют независимые кеши. Каталоги `learning`, `learning-v3`, `lyric-recovery-v3`, `tempo-v3` — версии внутренних форматов, а не версии приложения. Старые результаты открываются без перезаписи. Если части ещё не подготовлены, доступна кнопка «Подготовить части слов».

`POST /api/studio/jobs/{id}/melody` возвращает единую полную мелодию, повторно используя готовый совместимый v3-результат. Исторические `light/medium/pro` остаются только в API/файлах для совместимости. Новый клиент не предлагает выбор и не создаёт три одинаковых комплекта. `/tempo/full/{rate}` использует то же пианино. Исходный JSON скачивается отдельно от полного JSON со словами.

Ни наличие файлов, ни совпадение длительностей не доказывают акустическую точность. Для музыкальной оценки нужны прослушивание и независимая разметка; BL-001–BL-003 остаются в [бэклоге](docs/backlog.md).

## Проверка

```bash
PYTHONPATH=src .venv/bin/python -m pytest
node --test tests/studio_player.test.cjs
PYTHONPATH=src .venv/bin/python scripts/check_studio_browser.py --port 8082 --output output/browser-qa --data-dir output/browser-qa/data
PYTHONPATH=src .venv/bin/python scripts/check_reference_song.py --url http://127.0.0.1:8082
```

Постоянный пример — [Seekae: MP3, оригинальный RTF и TXT](references/seekae-test-and-recognise/README.md), явно разрешённый пользователем к хранению в Git. `--check-files-only` проверяет SHA-256 без сервера. При неизменных separation/ASR/F0 используется сохранённый анализ; `--reanalyze` запускает его заново. Скрипт проверяет 305 слов, полную мелодию и скорости, затем сообщает ссылку для проверки в браузере.

`/__checks` существует только в проверочном сервере. Калибровочные проверки запускаются отдельной кнопкой; для реальной песни откройте `/__checks?job={id}&full` и нажмите «Проверить читаемую шкалу и караоке». Отчёты остаются в `output/`, вне Git. Успех автоматических проверок не подменяет оценку пения пользователем.

Docker: `docker compose up --build`. Образ содержит FFmpeg, Rubber Band и зависимости студии; контейнер в этой итерации не запускался.
