# VocalCreator

**Рабочая демка 0.1 — принятый результат от 13 сентября 2026 года, только для десктопа.** Снимок `bfd2665`, ранее называвшийся 0.3, получил номер 0.1 без изменения алгоритмов и интерфейса, кроме номера версии. Актуальные ветки — `version-0.1` и `master`; прежние ветки 0.2 и 0.3 удалены.

[Контрольный результат и проверки](docs/vocal-studio-text-repair-verification.md) описывают полную лирику, части слов, две оси шкалы и изменение скорости. Названия ТЗ v1/v2/v3 и форматов `learning-v3`/`tempo-v3` сохранены для истории и совместимости данных. Независимая акустическая оценка остаётся отдельным исследованием; текущая демка принята пользователем.

Локальное приложение с двумя независимыми режимами:

- вокальная студия `MP3/WAV + точный TXT → вокал + минус + pitch + ноты + пианино`;
- прежний pipeline `MP3 + точный TXT → ASS → karaoke.mp4`.

Слова и тайминги сначала извлекаются из песни, затем глобально сопоставляются с TXT: отображаемый текст всегда остаётся пользовательским.

## Что уже работает

- MP3/WAV/FLAC/M4A/AAC/OGG через FFmpeg;
- базовая сетка распознанных слов через `faster-whisper` и уточнение доступных границ через WhisperX без потери ASR-слов;
- автоматическая очистка секционных заголовков и типового рекламного блока из скопированных lyrics без переписывания исполняемых строк;
- очищенный текст используется как `initial_prompt`, но display-слова по-прежнему берутся только из TXT;
- мягкий настраиваемый VAD и ручной сдвиг подсветки от −1000 до +1000 мс;
- глобальное монотонное сопоставление в стиле usersync, включая `никогда ↔ ни когда`, поэтому повторяющиеся строки получают разные времена;
- интерполяция нераспознанных слов с явной отметкой в JSON;
- диагностические `asr_text`, `match_similarity` и сводка качества в `alignment.json`;
- Demucs как опциональный separator с безопасным fallback на оригинал;
- ASS `\kt` + `\kf`, текущая + следующая строка, перенос длинных строк;
- procedural/solid/image/video background;
- H.264/AAC MP4, CLI, локальный Web UI, кеш и повторный render без ML;
- отдельный audio-only режим студии с постоянным манифестом, частичными результатами и повторным открытием после перезапуска;
- версия 1 `melody.json`: исходный F0-контур, устойчивые ноты, распевы и связи каждого слова со всеми пересекающими его нотами;
- три синхронные Web Audio дорожки «Вокал / Пианино / Минус», независимые gain/mute, Play/Pause, seek и масштаб;
- Light (одна учебная высота на слово), Medium (до двух последовательных высот), Pro (подробные события), пианино выбранного режима и горизонтальная прокрутка колесом;
- Apple Silicon без обязательной CUDA.

Полная подтверждённая спецификация: [docs/TZ.md](docs/TZ.md).

## Установка на macOS

```bash
brew install ffmpeg-full
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[ml,web,dev,separation,studio]'
```

`ffmpeg-full` keg-only и не ломает обычный `ffmpeg`; приложение само ищет `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`. Первая генерация скачает выбранную Whisper-модель и фонемную модель WhisperX для языка песни. Для русского по умолчанию выбрана компактная `bond005/wav2vec2-base-ru`; модель можно заменить через `alignment.align_models`. Стандартная ASR-модель `small` — компромисс скорости и качества; для сложного вокала можно выбрать `medium` или `large-v3`.

Для отделения вокала:

```bash
pip install -e '.[separation]'
```

Demucs на Apple Silicon запускается на CPU. Если он не установлен или падает в режиме `enabled: auto`, pipeline продолжит работу по оригиналу и честно укажет фактический `audio_mode` в `work/metadata.json`.

Это fallback только старого karaoke-режима. Студия никогда не выдаёт исходный mix за выделенный вокал: ошибка separator оставляет задание в состоянии `failed`.

Опциональный контрольный separator:

```bash
pip install -e '.[studio-roformer]'
```

`melband-roformer-infer` впервые скачивает checksum-verified checkpoint около 0,9 ГБ. На проверенной связке `melband-roformer-infer 0.1.5 + torch 2.8` операция complex `scatter` не поддерживается MPS, поэтому `auto` выбирает CPU. Фактический device, версия пакета и SHA-256 весов записываются в `studio.json`.

## CLI

### Вокальная студия

```bash
karaoke-gen studio \
  --audio ./song.mp3 \
  --lyrics ./lyrics.txt \
  --output ./studio-result \
  --input-type mix \
  --language en \
  --backend whisperx \
  --separator-backend demucs \
  --pitch-backend torchcrepe
```

Для уже выделенного голоса используйте `--input-type vocal`: минус при этом честно помечается отсутствующим. Диагностический `--pitch-backend autocorrelation` не является выбранной ML-моделью качества. Альтернативный separator запускается через `--separator-backend melband-roformer`; при необходимости device задаётся `--separator-device cpu`.

### Karaoke MP4

```bash
karaoke-gen \
  --audio ./song.mp3 \
  --lyrics ./lyrics.txt \
  --output ./output \
  --language en \
  --backend whisperx \
  --timing-offset-ms 0 \
  --audio-mode instrumental
```

Расширенная форма эквивалентна: `karaoke-gen generate ...`.

Другой фон:

```bash
karaoke-gen generate ... --background ./background.jpg
karaoke-gen generate ... --background ./loop.mp4
karaoke-gen generate ... --background solid
```

После ручной правки таймингов:

```bash
karaoke-gen render \
  --alignment output/alignment.json \
  --audio output/instrumental.wav \
  --output output/karaoke-edited.mp4 \
  --timing-offset-ms 0
```

Диагностика и Web UI:

```bash
karaoke-gen doctor
karaoke-gen web --port 8080
```

Откройте <http://127.0.0.1:8080>. Главная страница — студия; прежняя форма рендера доступна по `/karaoke`.

Готовые и частичные результаты студии сохраняются в `~/Library/Application Support/VocalCreator/jobs`. Каталог можно переопределить переменной `VOCAL_CREATOR_DATA_DIR`; внутри неё приложение создаёт `jobs/`. Процент не синтезируется: интерфейс показывает реальные состояния стадий. После перезапуска готовые результаты снова появляются в библиотеке, а незавершённые помечаются как прерванные.

После запуска генерации страница показывает реальный прогресс пяти стадий в процентах,
не перезагружается и по завершении выводит ссылки на артефакты и встроенное видео.
При ошибке её текст появляется в том же блоке прогресса.
В форме можно выбрать WhisperX/faster-whisper, размер модели, включить или отключить
мягкий VAD и сдвинуть подсветку в диапазоне от −1000 до +1000 мс.

## Тайминги и диагностика

Default новых запусков — offset 0 мс; явные значения в старых YAML не переписываются. Offset применяется один раз при рендере и не меняет аудио или канонические границы JSON. Заливка слова заканчивается на `end`, включая паузу перед следующим словом. `render` принимает `--timing-offset-ms` и создаёт отдельный `.render.json` с применёнными настройками.

Schema 3 читает JSON 1/2. Для ручной правки меняйте только `lines[].words[].start/end`: reader не подменяет их историческими значениями. `timing` хранит ASR-границы, кандидата уточнения, отдельные оценки и причины отказа/коррекции. Источники: `refined`, `asr`, `mixed`, `approximate_split`, `interpolated`, `manual`, тестовый `uniform`; отсутствующее происхождение старых файлов остаётся неизвестным. Деление составного слова использует доступные символьные границы, а деление по длине текста явно отмечается приблизительным.

`diagnostics` содержит модели, доступные ревизии, версии пакетов/рендера, фактические настройки, хеши входов и длительности стадий. Проверка шкалы сравнивает декодированный сигнал оригинала, подготовки и MP4; для Demucs проверяется сумма stem. `inconclusive` означает недостаток сигнала для доказательства, а `mismatch` останавливает генерацию.

ASR и уточнение имеют отдельные файлы в `work/timing-cache/`. Смена уточнителя или окна повторно использует ASR; оформление и offset не инвалидируют ML. Ключи учитывают фактический WAV и версии алгоритмов. Кеш при этом занимает дополнительное место, автоматической очистки нет.

В Web «Сопоставление текста» означает долю сопоставленных слов. Это не акустическая точность. Контекст уточнения настраивается через `alignment.context_seconds`, длина окна — `alignment.max_window_seconds`; `alignment.score_thresholds` задаёт порог для каждой модели. Default score 0,05 не откалиброван на песнях.

[Проверки без эталонов и контрольные видео](docs/timing-stability-report.md). [Как собрать корпус и сравнить модели](docs/timing-evaluation.md). [Отчёт об исправлении таймингов](docs/word-timing-implementation-report.md). Более тяжёлый уточнитель не объявлен точнее: реальная акустическая приёмка пока не выполнена.

## Ограничения и права

Акустические пороги студии пока не объявлены достигнутыми: для этого нужны независимая разметка, закрытый корпус и пользовательское A/B-прослушивание. RMVPE остаётся кандидатом сравнения и ещё не поставляется как рабочий backend. Синтез пианино локальный и зависимостей от внешних sample-pack не имеет.

Исторический API `learning` (этап v2) открывает исходные результаты и готовит учебные режимы из сохранённых данных без повторных separation, ASR и F0. Light выбран по умолчанию; последний успешный режим запоминается для результата в этом браузере. Смена режима сохраняет время, вид, масштаб и микшер. Исходные `melody.json` и `piano.wav` остаются отдельными файлами; скачивание учебного результата содержит режим в имени. Блок A–B удалён. Колесо над дорожкой и PageUp/PageDown перемещают вид, клик перематывает звук.

Без времён текста Light/Medium недоступны; при сомнительном времени слово может остаться без учебной ноты. Pro сохраняет подробный автоматический разбор, точность которого требует прослушивания. [ТЗ v2](docs/vocal-studio-tz-v2.md) и [отчёт проверки](docs/vocal-studio-v2-verification.md) разделяют программные результаты и открытую музыкальную приёмку.

Команды проверки студии:

```bash
.venv/bin/python -m pytest
node --test tests/studio_player.test.cjs
.venv/bin/python scripts/check_studio_browser.py --port 8082
# Откройте http://127.0.0.1:8082/__checks и нажмите «Запустить проверки браузера».
```

`check_studio_browser.py` использует отдельный каталог `output/v2-qa/browser-data` и сохраняет измерения в `output/v2-qa/browser-report.json`. Для подготовки частных фрагментов и пустой ручной разметки: `.venv/bin/python scripts/prepare_learning_acceptance.py /путь/к/сохранённому/result`. Пользовательское аудио и разметка остаются в исключённом из Git `output/`.

В исторической проверке прежнего karaoke pipeline были зарегистрированы две проблемы:

- **Потеря части слов при обработке песни с музыкой.** По отзыву пользователя, заметная часть текста в результате «съедается». Точные места и этап возникновения потерь пока не локализованы; отделение вокала и распознавание требуют дальнейшего анализа. Сохранение всех слов TXT в субтитрах само по себе не гарантирует, что для них найдены верные акустические границы.
- **Остаточное несовпадение подсветки с вокалом.** Некоторые слова подсвечиваются немного раньше или позже исполнения. Общий результат пользователь оценил положительно; точная величина остаточной ошибки на его последнем примере не измерена.

Это историческая запись. Потери лирики в нынешней студии локализованы и исправлены; последний результат и оставшиеся ограничения описаны в [отчёте исправления](docs/vocal-studio-text-repair-verification.md). Подробнее: [итог пользовательской проверки](docs/timing-stability-report.md#пользовательская-проверка-и-фиксация-версии).

Адлибы, перекрывающиеся голоса и отличающийся от записи текст могут потребовать ручной правки `alignment.json`. Инструмент не скачивает музыку или lyrics и не предоставляет каталог: используйте только файлы, которые вправе обрабатывать.

## Источники технических решений

- [WhisperX](https://github.com/m-bain/whisperX) — ASR + wav2vec2 word alignment.
- [usersync](https://github.com/iamjrmh/usersync) — проверенный паттерн mapping пользовательских lyrics на timestamp grid.
- [Demucs](https://github.com/facebookresearch/demucs) — two-stem vocal separation.
- [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html) — libass `ass` filter.


## Демка 0.1 — части слов и скорость

Полная каноническая лирика доступна в собственной текстовой области. В нотах видны произносимые части слова, а знак продолжения связывает одну часть с несколькими нотами. При неизвестной границе остаётся полное слово с объяснением. Качество автоматических частей не объявляется ручной фонетической разметкой.

Light / Medium / Pro сохраняют все устойчивые переходы без лимита нот на слово. Пока независимая калибровка упрощения не выполнена, три режима используют одинаковые события; интерфейс сообщает это прямо. Текст не создаёт дополнительные атаки пианино. Старые результаты сначала открываются с готовым аудио и полным текстом; кнопка «Подготовить части слов» создаёт производные данные в `learning-v3`.

Меню скорости содержит 0,25–2×. Для сохранения высоты нужен локальный Rubber Band 3+ (`brew install rubberband`). Один offline R3-процесс обрабатывает все каналы, сохраняя общую временную карту. Первая подготовка полной песни может занимать несколько минут; до готовности действует прежняя скорость, затем используется кеш `tempo-v3`. Исходные файлы не переписываются.

Колесо прокручивает высоту, горизонтальный жест — время, Shift + колесо — время. Масштабы «По времени» и «Высота нот» независимы. PageUp/PageDown меняют высоту, с Shift — время. Настольное окно допускает прокрутку до всех слов и обеих полос прокрутки.

Пример изолированного запуска демки:

```bash
PYTHONPATH=src .venv/bin/python scripts/check_studio_browser.py --port 8082 --output output/v3-qa --data-dir output/v3-qa/data
```

Постоянная пара [Seekae — MP3, оригинальный RTF и TXT](references/seekae-test-and-recognise/README.md) включена в репозиторий по поручению пользователя. Скрипт читает файлы из этой папки, без зависимости от Downloads и textutil. Проверить их без сервера: `.venv/bin/python scripts/check_reference_song.py --check-files-only`.

После каждого завершённого ТЗ или исправления проверяйте развёрнутую студию на этой паре:

```bash
PYTHONPATH=src .venv/bin/python scripts/check_reference_song.py --url http://127.0.0.1:8082
```

Скрипт сверяет SHA-256 MP3, исходного RTF и готового TXT, проверяет все 305 вхождений через API и готовит режимы/скорость. Если исходный анализ в библиотеке отсутствует, скрипт загружает эту пару в локальный продукт и ожидает завершения. При изменениях separation/ASR/F0 используйте `--reanalyze`; для производных данных используется совместимый сохранённый анализ. Затем обязательно откройте выданную ссылку в настоящем браузере, проверьте вид и воспроизведение и пригласите пользователя посмотреть результат. Успех API не подменяет эту проверку.

Предоставленный пример в `references/seekae-test-and-recognise/` — явно разрешённое исключение. Другие пользовательские файлы, кеши, ручные пометки и локальные отчёты остаются вне Git. Синтетические и браузерные проверки не заменяют пользовательское прослушивание и независимую разметку.

Расширение проверочного набора до **3 английских + 3 русских треков с лирикой** записано в [BL-001](docs/backlog.md). Сейчас готов EN-01 Seekae; ещё пять пар предстоит добавить.
